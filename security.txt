# BobaHack Virtual Clinic: AI Privacy & Security Layer

The codebase implements a strict privacy and security layer before and during the process of sending data to the AI. This is designed specifically to comply with healthcare data privacy laws (like HIPAA). 

Here is exactly how the security layer handles and protects patient data in the code:

### 1. In-Transit Security & JWT Authentication
Before any data reaches the AI, the backend intercepts the request using FastAPI dependencies. As seen in `api/sos.py`, endpoints use the `verify_jwt` middleware (`x_worker_id: str = Depends(verify_jwt)`). If the health worker does not have a valid, unexpired token, the payload is rejected immediately before any image processing occurs.

### 2. Local AI Inference (No Third-Party Cloud Leaks)
One of the most secure aspects of the architecture is that the AI models (`DenseNet121` / `TinyYOLOv3`) run **locally** on the FastAPI backend server. 
- In `main.py` (`/api/verify` and `/api/verify-video`), the app initializes `ImageRecognizer(EXECUTION_PATH, algorithm)`.
- Because the ML weights exist locally on the server, **patient images are never transmitted to third-party APIs like OpenAI or Google**. The data stays completely within the self-hosted backend.

### 3. Ephemeral "Zero-Trace" Temporary Storage
When the backend receives the Base64 image payload for AI analysis, it employs an ephemeral (temporary) file strategy:
```python
# A unique temp directory is generated for the specific request
req_temp_dir = os.path.join(TEMP_DIR, str(uuid.uuid4()))

try:
    # Run AI Prediction...
    predictions = recognizer.predict(images_path=req_temp_dir...)
finally:
    # CLEAN UP: This guarantees the images are instantly wiped 
    # from the disk the moment the AI finishes, even if the app crashes.
    if os.path.exists(req_temp_dir):
        shutil.rmtree(req_temp_dir)
```
This ensures that raw patient images are **never permanently stored on the backend disk**.

### 4. Post-Resolution Data Vanishing 
After the AI generates the summary and the Doctor reviews it, the frontend generates a localized PDF report for the patient. Once this is completed, a trigger is sent to the Supabase database to **permanently overwrite** the patient's sensitive fields (Name, Location, Case Description, and Images) with `[REDACTED FOR PRIVACY]`. 

By combining **JWT authentication**, **Local Model Execution**, **Zero-Trace Temp Storage**, and **Post-Resolution Redaction**, the codebase ensures that the patient data provided to the AI is entirely secure and leaves no lingering footprints on the server.
